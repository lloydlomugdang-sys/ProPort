# Portfolio export

The saved title-page flow remains Title Page → Summary → Export → Preview.
My Portfolios still uses the existing owner-scoped backend records. Export never
creates or updates a portfolio record. A reopened preview can export the same
saved title page again with the account's current documents.

## Formats and dependencies

- PDF: `pdf` 3.12.0, compatible with the installed Dart 3.11 SDK (3.13 requires
  Dart 3.12). A4 pages, section headings, page numbers and bundled Noto Sans
  regular/bold fonts. Fonts are offline assets licensed under the accompanying
  SIL Open Font License. No font downloads happen at export time.
- DOCX: a minimal Office Open XML ZIP generated with existing `archive` 4.0.9
  and `xml` 6.6.1 packages, now direct dependencies. The document contains A4
  page settings, explicit paragraph/run formatting, and seven section breaks.
  No Office/LibreOffice runtime, macros, remote references or templates.
- Storage: existing `path_provider` 2.1.5, now direct.
- Sharing: `share_plus` 11.1.0, compatible with the existing Android Gradle
  plugin 8.11.1. More recent share_plus versions require a toolchain upgrade.
  The plugin's own FileProvider grants temporary access to the selected file;
  broad storage permissions are not needed.

The lockfile pins resolved dependencies. Platform plugin registrants are
regenerated by Flutter, including desktop registrations for transitive plugins.

## Content and boundaries

Both formats explicitly project the title-page fields plus public document
title, date, category/folder, original filename, description and manual
reflection. Authentication tokens, database IDs and storage keys are never
included by the exporter. Data comes from the existing authenticated
DocumentService; no client-controlled owner ID is introduced.

Original images and uploaded PDF pages are **not embedded** in this phase.
The protected backend content endpoint exists, but the existing Flutter
authenticated transport supports JSON rather than bounded binary downloads.
This implementation leaves that transport and authentication unchanged and
clearly discloses the metadata-only representation in the UI and both formats.
Adding bounded authenticated image downloads and image decoding is future work.

The existing list API returns at most 100 documents. If the server summary
reports more entries than the returned list, both files and the success message
explicitly say how many were included and that the export is incomplete. Counts
are never fabricated. Original-file embedding and pagination are not claimed.

The preview is live account metadata, not a PDF/DOCX viewer or frozen historical
document snapshot. The generated file is the snapshot taken when Export is tapped.

## Storage and sharing

Generation runs on a background Dart isolate. The finished bytes are written to:

`<app temporary directory>/gradport_exports/export_<unique>/GradPort_<safe-name>_Portfolio.pdf`

or `.docx`. Filenames are length-bounded and restricted to safe characters; each
export uses a separate directory. A failed write attempts to remove only its own
partial file/directory. These are app-cache copies, not durable library records;
the OS can evict them. Use **Share** to send the file or save it with an available
Android share target (for example Files/Drive). Sharing is explicit and its
dismissal is never reported as a successful external save. No separate Open
handler or legacy storage permission is required.

## Verification and release checks

Run `flutter test` and `flutter analyze`. Export tests inspect real PDF text,
DOCX XML/ZIP structure, safe filenames, actual temporary file writes, background
generation, progress/errors, duplicate taps, persistence and preview navigation.
Widget tests replace only OS sharing/storage; encoding is real.

For optional independent PDF.js validation, with existing backend dependencies:

```powershell
flutter test test/portfolio_export_service_test.dart --dart-define=EXPORT_FIXTURE_DIR=.dart_tool/export_qa
node test/support/inspect_portfolio_export.mjs --render
```

Only synthetic fixture data is used. No database access or backend changes are
needed. Before release, on a real Android device: export both formats, save/share
them, open PDF in a reader and DOCX in Word/Docs, test cancel/error paths, and
restart/login to reopen and re-export a saved portfolio.
